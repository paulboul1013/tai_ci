# JS DOM 補齊：切片 7 收尾驗收（2026-10-04）

狀態：VALIDATING。計畫與各切片紀錄見 [JS DOM 計畫](../js-dom-plan.md)；刻意差異 D1、D2、D4–D13
見 `PORTING_PLAN.md`「已知差異與範圍」。本檔是整個 JS DOM 工作（切片 0–7）的驗收；切片 5 的細節另見
[cookie／XHR 驗收](2026-09-29-js-cookie-xhr.md)。

## 證明了什麼

- **Oracle 比對：** `python3 tests/js_dom_oracle_probe.py --check` 連跑三次輸出相同。凍結 27 個情境＋
  11 個 scheduling 情境（共 38），收尾新增 `script_dispatch_event`（腳本直接呼叫 `new Event`／
  `dispatchEvent`：不冒泡、回傳 `do_default`；同型別的頁面派送會冒泡），重新凍結時原 37 個答案不變。
  `js_dom_differential` 38 個情境全部相符（0 pending）；`js_dom_integration`、`js_page_oracle_probe`、
  `title_integration`、`inline_script_integration`、`tabset_xhr`、`raf_window`、`timer_window` 通過。
- **差異規則範圍（獨立 oracle-checker 稽核）：** D7 只套 `listener_throws` 第 1、3 步，D10 只套
  `raf_throws` 第 1 步，D5 只套 `scheduling_globals`／`xhr_open` 與 `xhr.loaded` 的 `async` 紀錄，D8 只
  套 `focus.after_key` 的 `focus`；覆寫值都是確切值，沒有整個情境跳過。故意竄改 native 輸出時測試
  會失敗（新增 `script_dispatch_event` 前，共 37 個）：改一個 tag 讓 20/37 個情境失敗，`raf_requests`
  加一讓 3/37 個失敗。
- **配置故障（`tests/test_js_oom.c`，CTest `js_dom_oom`）：** 情境涵蓋 createElement、insertBefore、
  appendChild、removeChild、setAttribute（ID 同步）、innerHTML／outerHTML、document.cookie、同步與
  非同步 XHR、listener、RAF、timer。三種模式：從第 N 次 malloc 起全部失敗、只有第 N 次失敗（各約
  160 個點），以及把 JS heap 上限設在已用量之上 N 位元組、以 16 位元組為一步（約 570 輪，涵蓋
  QuickJS 自己的配置；QuickJS 的 arena 讓小物件不經 malloc）。每輪檢查不崩潰、樹的父子指標一致、
  深度不超過 D13；ASan＋LSan 下無洩漏。故意讓 `innerHTML` 在 OOM 時不釋放 fragment，LSan 立即
  報出 22,628 bytes 洩漏。
- **Xvfb 真實視窗（Debug 二進位檔，未開 LSan）：** 7 個情境：點擊 listener 改 DOM 與標題、丟錯
  listener 後其他 listener 照跑且視窗仍可輸入（D7）、keydown 移除焦點 input 後不再派送（D8）、
  RAF 動畫 600 frame、setTimeout／setInterval／clearInterval、cookie＋同步／非同步 XHR（伺服器紀錄
  帶 Cookie）、WM_DELETE_WINDOW 關閉 exit 0。另 5 個深度情境：50,000 層 `<div>` 頁面顯示並可捲動
  （修正前 SIGSEGV）、點擊迴圈 appendChild 在 511 停下並顯示 `Document depth limit reached`、點擊
  設定 5,000 層 innerHTML、40,000 個 id 的頁面載入後標題為 `object`（修正前載入失敗）、正常關閉。
- **Sanitizer：** 刪除專案物件檔完整重編後 Debug CTest 54/54；`build-asan/` ASan/UBSan＋LSan（`detect_leaks=1`，只排除
  `leak:libfontconfig.so`、`leak:libcairo.so`）53/54：`presentation_dummy` 在 `-j 2` 平行執行時書籤頁斷言
  失敗（`tests/test_presentation.c:1112`，沒有任何 sanitizer 報告），單獨重跑 3/3 通過；其餘 53 項含
  `js_dom_oom` 全部通過，無 ASan／UBSan／LSan 錯誤。ASan headless 載入 600／50,000 層與腳本建出的
  深樹並截圖，無錯誤。
- **獨立審查（`ownership-reviewer` 三輪：切片 0–6b 全部、收尾修正、格式元素與 crash 回報修正）：** 三條綁定邊界成立（`dom.h` 不含 JS 型別；handle 轉換
  只在 `js.c`；凍結 `runtime.js` 原文嵌入、native JS 在 `js_prelude.js`／`js_scheduling.js`）。節點
  所有權、JSValue 生命週期、XHR job 跨執行緒、導覽與關閉時取消、stale callback 都檢查為乾淨。
  建置注意：WSL 時鐘倒退曾讓 Ninja 沿用舊物件（一次 ASan 失敗與一次無效的竄改實驗都因此發生），
  最終兩套測試前刪除了所有專案物件檔再完整重編。
  找到並已修正的缺陷見下節。

## 主要缺口

- **既有測試隔離問題（非本工作造成）：** dummy SDL 測試經 `tai_tabset_create_with_home_url` 開啟預設
  書籤檔，CTest 未設定 `XDG_DATA_HOME`，所以測試會讀寫使用者真實的
  `~/.local/share/tai-browser/bookmarks`，平行執行時互相干擾，造成上述 `presentation_dummy` 偶發失敗。

- Detached 節點到文件銷毀才回收（D2），wrapper 不唯一；升級路線見計畫「綁定升級路線」。
- `fetch`、capture phase、`parentNode` 等 runtime.js 沒有的 API 不在範圍內。
- 事件期 XHR 的 30 秒逾時沒有可注入的短時限；「非同步 XHR 進行中關閉分頁／程式」沒有專門的
  LSan 斷言（由 `tabset_xhr` 與 ASan 全套間接覆蓋）。
- `js_dom_oom` 只檢查不崩潰、樹一致與無洩漏，不斷言丟出的例外種類。
- Xvfb 真實視窗使用 Debug 二進位檔，未開 sanitizer；inline script 的執行只在 headless 與
  `inline_script_integration` 驗證。
- D13 上限以下的 `<p>`／`<li>` 隱含關閉與 Python 不同；Debug 建置中 40,000 個元素的 layout 約需
  20 秒（既有 layout 效能，與 JS 無關）。
