# 完整管線 E2E（2026-10-29）

狀態：VALIDATING。

## 目標

證明 `ACCEPTANCE.md` 的條件：Navigation→resource loading→script/style→layout→raster→presentation
的 native E2E 通過。計畫、決定 E1–E6 與 seams 見 [docs/e2e-plan.md](../e2e-plan.md)。

## 做了什麼

- `tests/e2e_fixture.py`：127.0.0.1 的 `E2EServer`。`/` 302 到 `/index.html`；外部 CSS 以 gzip、
  外部 JS 以 chunked 回應，JS 新增 `<p>`、改 `<title>`、設 cookie；表單頁 POST 到 `/submit`，
  結果頁回顯收到的欄位；`/inline.html` 只給 native（D6）。伺服器記錄 method、path、Cookie、body。
- `tests/e2e_shape.py`：把 oracle 與 native 的輸出轉成同一種檢查點（url、title、history、scroll、
  dom、layout、display、inputs、requests）。只正規化三件事：port 換成 `PORT`、requests 排序
  （oracle 平行抓 CSS 與 JS）、native `InputLayout` 拿掉 `word`（使用者 2026-10-29 決定 A）。
- `tests/e2e_oracle_probe.py`：凍結 Python 的 7 個檢查點到 `tests/fixtures/e2e_oracle.json`
  （open、fragment、form、filled、submit、back_form、back_index）。
- `tests/test_e2e_window.c`＋`tests/e2e_integration.py`：dummy SDL 下以 SDL 事件跑同一劇本，
  逐點比對（數值容差 0.0001）。
- `tests/e2e_window_integration.py`：Xvfb 真實視窗（`window_session.sh`），真實 X11 點擊與打字；
  每步比對請求紀錄、視窗標題、截圖區域顏色，並檢查 SDL 事件紀錄；缺 Xvfb 等工具時回傳 77（CTest skip）。

## 證明了什麼

- **Oracle：** `e2e_oracle_probe --check` 重複執行結果相同。
- **找到真的缺口：** 第一次比對在 `fragment`／`back_index` 失敗，原因是 native 沒有 `:visited`
  標記；依使用者決定先補上（見 [2026-10-29-visited.md](2026-10-29-visited.md)），之後 7 個檢查點全部相符。
- **測試會變紅：** 拿掉 native 的 `Cookie` header（`src/network.c`）→ `pipeline.form /requests/0/cookie`
  失敗（之後還原）。
- **真實視窗：** 截圖顯示 banner 底色（CSS 載入）、捲動到 `#bottom`（fragment）、輸入值與勾選、
  結果頁、Back 後連結變黑（`:visited`）、inline script 塗上的 `#00aa55`。
- **CTest：** 73/73。
- **ASan-UBSan-LSan**（suppression：`libfontconfig.so`、`libcairo.so`、`X11_InitModes_XRandR`）：
  e2e_oracle_probe、e2e_integration、e2e_window_integration、visited、visited_window、
  overflow_scroll_integration、history 相關，共 10/10。
- **獨立審查：** Standards、Spec 兩軸；發現（viewport 欄位、重複的 navigate、散落的字串、
  初始化失敗未關 server、計畫檔過時）已處理。

## 與計畫的差異

- 「Back 兩次」拆成 `back_form`、`back_index` 兩個檢查點。
- 頁面寫在 `tests/e2e_fixture.py`，沒有 `tests/fixtures/e2e_site/` 目錄。
- 302 後兩邊的 URL 都保留請求的 `/`。
- native 與 Python 的 tab 高度不同（`PORTING_PLAN.md`「Tab 列換行時的 viewport」），所以 `#bottom`
  放在捲動上限以內，讓捲動位置等於目標的 y（198）。`viewport` 欄位只記錄 Python 的值。

## 剩餘缺口

- 真實視窗的 `filled` 步驟只截圖，輸入值由 SDL 事件紀錄與 POST body 間接證明。
- 不涵蓋 view-source、resize、多 tab、多視窗、書籤（ACCEPTANCE 的「代表性 E2E」條件）。
- 不做 Python 與 native 的逐像素比對（2026-10-14 決定）。
