# 常用 DOM API（D14，2026-11-01）

狀態：VALIDATING。

## 問題

凍結的 `runtime.js` 只有 `getAttribute`、`setAttribute`、`children`、`innerHTML`、`appendChild`
等少數 API。真實網頁常用的 `parentNode`、`textContent`、`classList` 讀到 `undefined`，listener
在下一行就丟 `TypeError`。

## 新增

- `src/js_prelude.js`：`parentNode`、`parentElement`、`tagName`、`textContent`、`className`、
  `classList`（add／remove／toggle／contains）、`document.getElementById`、`document.querySelector`。
  凍結的 `runtime.js` 沒有修改。
- `src/js.c`：5 個 bridge operation（`parentNode`、`getElementById`、`tagName`、`textContent_get`、
  `textContent_set`）。`<html>` 的父節點以 -1 回報，前言 JS 換成 `document`。
- `src/dom.c`／`include/tai/dom.h`：`tai_node_set_text_content`、`tai_node_text_content`、
  `tai_node_find_by_id`。不含 JS 或 handle。
- `tests/test_js.c`：`test_common_dom_api`；`test_node_limit`、`test_depth_limit` 各加一個
  `textContent` 檢查。
- `tests/js_dom_differential.py`：`D14_EXPECTED` 記錄 `children_and_handles` 第 3 步的差異。

使用者決定（2026-11-01）：`<html>.parentNode` 是 `document`；`tagName` 大寫；`textContent` 含
script／style 文字。

## 證明了什麼

- **逐項斷言：** `test_common_dom_api` 涵蓋三項決定、detached 節點的 `parentNode` 為 null、
  `textContent` 寫入不解析 HTML 且回報被移除的節點、`null`／`undefined` 清空、被移除元素的
  ID 全域消失、`classList` 去重複與只以 ASCII 空白分隔、沒有 class 屬性的元素不會多出
  `class=""`、`toggle` 的 force、`querySelector` 無效 selector 與 `querySelectorAll` 丟同樣的錯、
  `getElementById` 重複 ID 回傳第一個、數字參數、空字串與 detached 元素。節點上限與深度上限
  下寫入 `textContent` 會丟錯且樹不變。
- **突變：** 三個一次性突變都讓 `test_js` 變紅：`<html>.parentNode` 改回 null、`undefined`
  寫成 `"undefined"`、`classList` 一律寫入 class 屬性。
- **Xvfb 真實視窗：** 點按鈕兩次，`parentNode.classList.add('open')` 讓卡片變淺藍，計數
  `textContent` 變 2，`<title>` 變 `clicked 2 BUTTON card open`；browser `exit=0`。trace：
  1 次 `Tab.load`、1 次 `JSContext.run`、2 次 `Tab.click`，每次點擊後一次 `render`。
- **回歸：** 整套 CTest 80/80 兩次；ASan-UBSan-LSan 的 JS／DOM 測試 10/10（含配置故障掃描
  `js_dom_oom`）；`js_dom_differential` 只有記錄的 D14 差異。
- **審查：** `ownership-reviewer` 無 blocker／should；Spec 與 Standards 審查的 should 都已修正
  （`undefined` 清空、`classList` 不建立空 class、測試缺口、改用既有的 `expect_text`、
  `getElementById` 的走訪移到 `dom.c`）。

## 剩餘缺口

- wrapper 不唯一：兩次讀取 `parentNode` 以 `===` 比較為 false（候選 C「wrapper 唯一」）。
- `nodeType`、`document.body`、`nextSibling`、`childNodes` 等仍沒有；JS 拿不到文字節點。
- `classList.add('')` 與含空白的 token 不丟 `SyntaxError`／`InvalidCharacterError`。
- `js_dom_oom` 沒有專門走新 operation 的配置故障路徑。
- 驗證中發現：用 Bash／python 修改的檔案不會觸發清除舊物件檔的 hook，WSL2 時鐘倒退時 ninja
  會沿用舊 binary；本次證據都是在 `tests/tools/clear_stale_objects.sh` 之後重新建置取得。
