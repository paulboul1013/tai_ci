# Trace（`MeasureTime` 移植）— 2026-10-14

## 範圍

Python `MeasureTime`（`tests/reference/browser.py:665`）的 Chrome／Perfetto JSON trace 移植到
`src/trace.c`。`tai-browser --window` 在 `BROWSER_TRACE_FILE` 非空時寫 trace；未設或空字串不建立檔案。
刻意差異 D-T1～D-T8 記在 `PORTING_PLAN.md`。

## 設計

opus 與 sonnet 各提一份設計，再由 sonnet 獨立評審，評審與主導者都選 opus 版為基礎。關鍵理由：
loader 以單一 libcurl multi 交錯處理請求，所以 document、子資源與非同步 XHR 改用帶 id 的 async
`b`/`e`，同步執行到結束的工作才用 B/E。事件名稱由 `TaiTraceSpan`／`TaiTraceFetchKind` 索引同一張
名稱表，呼叫端無法自創名稱。

## 名稱表與 oracle 證據

`tests/trace_oracle_probe.py` 在 Xvfb 上跑 Python `BrowserApp.run()`，載入
`tests/fixtures/trace_window/`，並凍結 oracle 的事件名稱（`tests/fixtures/trace_oracle.json`）；
連跑 3 次名稱集合相同。native 發出的每個名稱 oracle 都有。oracle 有、native 不發的 span 只有
`commit`。

| 執行緒 | native 事件 |
|---|---|
| Loader thread | `javascript`、`render`、`Task: Tab.load`、`Task: Tab._finish_document_load`、`Task: Tab._finish_page_resources`、`Task: JSContext.run`；async：`Network I/O: document`、`resource_fetch[i]: script\|style`、`Network I/O: asynchronous XHR` |
| Browser thread | `javascript`、`render`、`Task: Tab.run_animation_frame`、`Task: Tab.click`、`Task: JSContext.dispatch_settimeout`／`dispatch_setinterval`／`dispatch_xhr_onload`、`Network I/O: synchronous XHR`、`raster_and_draw`、`sdl_present` |

`resource_fetch[i]` 的 i 比照 Python：計入 inline style、不計 inline script。oracle trace 為
`resource_fetch[1]: style`、`resource_fetch[2]: script`；刻意拿掉這項調整時，整合測試會失敗並出現
`resource_fetch[3]: script`。

## 驗證

- `ctest --test-dir build --output-on-failure -j 3`：58/58 通過。
- `LSAN_OPTIONS=suppressions=<leak:libfontconfig.so, leak:libcairo.so> ctest --test-dir build-asan --output-on-failure -j 3`
  （`-DTAI_SANITIZERS=ON`）：58/58 通過，LSan 有執行。`trace_window_integration` 另外加
  `leak:X11_InitModes_XRandR`：SDL 在 Xvfb 上初始化 video 時，經 dlopen 載入的 libXrandr 洩漏 8 bytes，
  stack 上沒有專案 frame。
- `trace`：關閉狀態、檔案結構、開檔失敗、執行緒命名與重開後的 generation、fetch id 與跳脫。
  `trace_format`：多執行緒壓力測試，拿掉 mutex 時會失敗。
- `trace_window_integration`：Xvfb 真實視窗，用 `tests/tools/window_session.sh` 驅動，涵蓋 timer、
  interval、非同步與同步 XHR、外部 script 與 stylesheet、rAF、點擊。檢查 B/E 巢狀、`b`/`e` 配對、
  執行緒名稱與必要事件。另外檢查三種設定：未設與空字串都不建立檔案，無法寫入的路徑會 exit 1。
- 取消與關閉路徑（2026-10-14 補測）：`trace_window_integration` 另起本機 127.0.0.1 伺服器，`/hang*`
  請求在瀏覽器結束前一律不回應，所以這些請求的 `e` 只能來自取消或關閉路徑。三個情境如下。
  `navigate`：document 卡住時改導覽，再導覽離開有非同步 XHR 未完成的頁面，接著在 stylesheet 卡住時
  再導覽。`close-loading`：stylesheet 卡住時關閉視窗。`close-xhr`：非同步 XHR 未完成時關閉視窗。
  測試要求每個 `b` 都有同 id 的 `e`，各名稱的配對數也必須完全符合預期。
  突變驗證有三組：
  - 拿掉 `tai_page_load_async_cancel` 的 `tai_trace_fetch_end`，測試失敗，訊息為 `async slices left open:
    {1: 'Network I/O: document', 5: 'resource_fetch[0]: style'}`。
  - 只拿掉 loader 結束時的 `async_expire(…, "browser is closing")`，測試仍通過。原因是關閉視窗時頁面
    先銷毀，XHR 被標為 abandoned，由 `loader_service` 的 `async_expire(loader, NULL)` 收尾；結束時那次
    呼叫只是後備。
  - 兩層都拿掉，測試失敗，訊息為 `{3: 'Network I/O: asynchronous XHR'}`。
  手動在 Xvfb 跑 `navigate` 情境並讀 trace：每個被取消的 `e` 都緊接在下一個 document 的 `b` 之前，
  XHR 的 `e` 在 `done.html` 載入後 23 ms 出現，截圖顯示 `done.html`。
  Debug 版 2/2 通過。ASan-UBSan-LSan 版直接執行 3/3 通過，經 CTest 執行 2/4 通過。兩次失敗都在既有的
  `traced_run` 關閉步驟，`stop` 沒有輸出 `browser exit=`，log 裡也沒有 sanitizer 錯誤。之後連續 5 次
  都無法重現，原因未查明。
  後續追查：失敗那次留下一個孤兒 `Xvfb`，代表 `window_session.sh stop` 在停止 Xvfb 之前就中止了。
  已排除三種原因：瀏覽器結束得慢（`close` 回傳時都已結束）、symbolizer 冷啟動、PID 回繞。
  推測是 `cmd_stop` 的 `alive` 與 `readlink`／`kill -TERM` 之間，瀏覽器剛好結束並被回收，但沒有重現。
  `Session.stop()` 已修正：失敗訊息會帶 `stop` 的 rc 與 stderr，失敗時 `abandon()` 會再收一次，
  不再遺留 Xvfb。修正後經 CTest 連跑 8 次 ASan 版，8 次都通過。
- 主導者另外手動跑了一次 Xvfb 視窗並讀 trace 內容：兩條執行緒的事件分佈與上表相符，共 87 個事件。
- 獨立審查（`ownership-reviewer`）沒有發現缺陷。審查確認的項目：
  - 每條路徑的 B/E 與 `b`/`e` 都成對，包含取消、逾時、loader 結束與 submit 失敗。
  - 關閉順序正確，loader join 之後才寫 `]}`。
  - `browser.c` 的 `*_body` 拆分是純抽取，非 trace 行為沒有改變。
  - `python_resource_index` 與 oracle 的 `_collect_page_resources` 一致。
